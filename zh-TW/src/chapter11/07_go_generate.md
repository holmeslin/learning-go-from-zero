# `//go:generate`

## 本集目標

學會用 `//go:generate` 把「產生程式碼的指令」寫在原始碼裡，再用 `go generate` 一次執行，並認得自動產生的檔案。

## 正文

### 讓程式幫你寫程式

有些程式碼很規律、很長，手寫又容易出錯，例如一大張預先算好的表格、每個常數對應的名字、從資料定義轉出來的程式碼。這種時候，與其手寫，不如**寫一個小程式來產生它**。

問題是：產生程式碼的指令要記在哪裡？下次修改後，其他人怎麼知道要重新產生？Go 的答案是把指令直接寫在原始碼裡：

```go,ignore
//go:generate go run gen.go
```

這行看起來像註解，但 `go generate` 這個指令會掃描所有 `.go` 檔，找出 `//go:generate` 開頭的行，依序執行後面的指令。和 `//go:embed` 一樣，`//` 和 `go:` 之間不能有空格。

### 完整例子：產生平方表

假設程式需要一張 0～9 的平方表。資料夾有兩個檔案：

```text
myapp/
├── go.mod
├── gen.go
└── main.go
```

`main.go` 使用一個叫 `squares` 的變數，但它還不存在：

```go,ignore
package main

import "fmt"

//go:generate go run gen.go

func main() {
	fmt.Println("7 的平方是", squares[7])
	fmt.Println("表格共有", len(squares), "個數字")
}
```

`gen.go` 是負責產生程式碼的小程式：

```go,ignore
//go:build ignore

package main

import (
	"fmt"
	"os"
	"strings"
)

func main() {
	var b strings.Builder
	b.WriteString("// Code generated by gen.go; DO NOT EDIT.\n\n")
	b.WriteString("package main\n\n")
	b.WriteString("var squares = []int{\n")
	for i := range 10 {
		fmt.Fprintf(&b, "\t%d,\n", i*i)
	}
	b.WriteString("}\n")

	err := os.WriteFile("squares_gen.go", []byte(b.String()), 0o644)
	if err != nil {
		fmt.Println("錯誤:", err)
		return
	}
	fmt.Println("已產生 squares_gen.go")
}
```

- 最上面的 `//go:build ignore` 是上一集的 build tag：`gen.go` 平常**不參與編譯**，否則同一個資料夾就會有兩個 `main` 函式。它只會在 `go run gen.go` 指名執行時才被編譯。
- 程式用 `strings.Builder` 一段一段組出新檔案的內容。`fmt.Fprintf` 和第 4 章的 `fmt.Fprintln` 一樣，把輸出寫到指定的地方，只是可以用格式動詞。
- `os.WriteFile` 把內容寫成檔案，`0o644` 是檔案權限；檔案操作第 12 章會正式介紹。

### 執行 `go generate`

還沒產生之前，`squares` 不存在，程式根本編譯不過。先執行：

```bash
go generate
```

執行結果：

```text
已產生 squares_gen.go
```

資料夾裡多了 `squares_gen.go`：

```go,ignore
// Code generated by gen.go; DO NOT EDIT.

package main

var squares = []int{
	0,
	1,
	4,
	9,
	16,
	25,
	36,
	49,
	64,
	81,
}
```

現在就能正常執行了：

```bash
go run .
```

執行結果：

```text
7 的平方是 49
表格共有 10 個數字
```

加上 `-x` 參數，`go generate -x` 會先印出每一條要執行的指令，方便確認它到底做了什麼。

### 幾個要記住的規則

- **`go generate` 不會自動執行**。`go build`、`go run`、`go test` 都不會幫你跑，要自己手動下指令。改了產生器或它依賴的資料後，記得重新產生。
- 產生出來的檔案**要一起放進版本控制**。其他人拿到程式碼就能直接編譯，不用先裝產生器。
- 第一行 `// Code generated ... DO NOT EDIT.` 是 Go 的固定慣例。工具和編輯器看到這行，就知道這是自動產生的檔案，會提醒你不要手動修改，因為下次產生時會被蓋掉。要改，就改產生器。

### 常見的產生器

實務上，很多產生器是現成的工具。最有名的是 `stringer`，它會替一組用 `iota` 定義的常數自動產生 `String()` 方法（第 4 章的 `fmt.Stringer`）。它不在標準函式庫裡，要先用 `go get -tool golang.org/x/tools/cmd/stringer` 把它登記成這個模組的工具（Go 1.24 起的功能，用法和第 8 章的 `go get` 類似），之後就能寫：

```go,ignore
//go:generate go tool stringer -type=Color
```

## 重點整理

- `//go:generate 指令` 把產生程式碼的指令寫在原始碼裡，執行 `go generate` 時才會依序執行。
- `go build`、`go run` 不會自動執行 `go generate`；`-x` 可以印出執行的指令。
- 產生器常放在帶有 `//go:build ignore` 的檔案裡，用 `go run gen.go` 執行，避免和主程式一起編譯。
- 產生的檔案第一行寫 `// Code generated ... DO NOT EDIT.`，要提交進版本控制，修改時改產生器而不是改產生的檔案。
