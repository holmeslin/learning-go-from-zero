# 切片共用底層陣列

## 本集目標

理解切片共用底層陣列時會發生什麼事，以及 `append` 什麼時候會「分家」。

## 正文

上一集說，`s[a:b]` 做出的新切片和原本的切片看著同一個底層陣列。這會帶來一些乍看很奇怪的結果，但只要記得「切片是窗戶」，就都說得通。

### 改一邊，另一邊也變

```go
package main

import "fmt"

func main() {
	a := []int{1, 2, 3, 4, 5}
	b := a[1:3]
	b[0] = 99
	fmt.Println("a:", a)
	fmt.Println("b:", b)
}
```

執行結果：

```text
a: [1 99 3 4 5]
b: [99 3]
```

我們只改了 `b[0]`，`a` 卻也跟著變了。因為 `b[0]` 和 `a[1]` 是底層陣列裡的**同一格**，兩扇窗戶看著同一個置物櫃。

賦值也是一樣，`c := a` 不會複製元素，`c` 只是另一扇看著同一個底層陣列的窗戶。

### `append` 在容量內：蓋掉別人的資料

更容易踩到的是 `append`。`b` 的長度是 2，但容量是 4（從 `a[1]` 算到最後）。對 `b` 做 `append` 時，容量還夠，就會直接寫進底層陣列的下一格：

```go
package main

import "fmt"

func main() {
	a := []int{1, 2, 3, 4, 5}
	b := a[1:3]
	fmt.Println("b 的 len", len(b), "cap", cap(b))

	b = append(b, 99)
	fmt.Println("a:", a)
	fmt.Println("b:", b)
}
```

執行結果：

```text
b 的 len 2 cap 4
a: [1 2 3 99 5]
b: [2 3 99]
```

```text
底層陣列： [ 1 | 2 | 3 | 99 | 5 ]
a：        └──────── 長度 5 ────────┘
b：            └─ 長度 3 ──┘
```

`b` 的下一格剛好就是 `a[3]`，於是 `a` 原本的 4 被蓋成了 99。這種 bug 很難發現，因為我們明明沒有動 `a`。

### `append` 超過容量：分家

如果 `append` 超過容量，上一集說過，Go 會配置一個新的底層陣列並把元素複製過去。從這一刻起，兩個切片就「分家」了：

```go
package main

import "fmt"

func main() {
	a := []int{1, 2, 3, 4, 5}
	b := a[3:]
	fmt.Println("b 的 len", len(b), "cap", cap(b))

	b = append(b, 6)
	b[0] = 99
	fmt.Println("a:", a)
	fmt.Println("b:", b)
}
```

執行結果：

```text
b 的 len 2 cap 2
a: [1 2 3 4 5]
b: [99 5 6]
```

`b` 的容量是 2，已經滿了。`append(b, 6)` 只好配置新陣列，把 4、5 複製過去再放入 6。之後再改 `b[0]`，改的是新陣列，`a` 完全不受影響。

### 怎麼記？

- 多個切片可能共用同一個底層陣列，改元素會互相影響。
- `append` 時：容量夠，寫進原本的底層陣列（可能蓋掉別人看得到的資料）；容量不夠，換新陣列，從此分家。
- 你通常無法一眼看出容量夠不夠，所以**不要依賴**「會不會分家」來寫程式。需要一份互不影響的資料時，就明確地複製一份，下一集的 `copy` 就是為此而生。

## 重點整理

- 從同一個切片切出來的切片（或直接賦值的切片）共用底層陣列，改元素時彼此看得到。
- 容量還夠時，`append` 會直接寫進共用的底層陣列，可能蓋掉其他切片的資料。
- 超過容量時，`append` 會配置新陣列，新切片與舊切片從此不再共用。
- 想要互不影響，就明確複製一份。
