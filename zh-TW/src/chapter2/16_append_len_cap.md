# `append`、`len`、`cap`

## 本集目標

用 `append` 在切片尾端加入元素，並用 `len` 和 `cap` 觀察切片的長度與容量。

## 正文

### `append`：加到最後面

```go
package main

import "fmt"

func main() {
	var names []string
	names = append(names, "小明")
	names = append(names, "小華")
	names = append(names, "小美", "阿強")
	fmt.Println(names, len(names))
}
```

執行結果：

```text
[小明 小華 小美 阿強] 4
```

`append(切片, 值...)` 會把值加到切片尾端，一次可以加一個或好幾個。

最重要的是要**把結果接回來**：`names = append(names, ...)`。`append` 會**回傳**加入元素後的切片，原變數的長度不會自動更新，但底層陣列可能被寫入。單獨呼叫 `append` 卻不用它的結果，Go 會拒絕編譯。

從 `nil` 切片開始 `append` 完全沒問題，這是 Go 裡建立切片最常見的方式之一。

### `cap`：容量

上一集說切片有長度和容量。長度用 `len` 看，容量用 `cap` 看：

```go
package main

import "fmt"

func main() {
	var nums []int
	for i := range 6 {
		nums = append(nums, i)
		fmt.Println("len", len(nums), "cap", cap(nums))
	}
}
```

執行結果（某一次）：

```text
len 1 cap 4
len 2 cap 4
len 3 cap 4
len 4 cap 4
len 5 cap 8
len 6 cap 8
```

- **長度**：切片目前裝了幾個元素。
- **容量**：底層陣列有幾格可以用（從切片的起點算起）。

### `append` 背後發生了什麼

底層陣列跟上一集的陣列一樣，大小是固定的。所以 `append` 會這樣做：

1. **容量還夠**（加完所有新元素後，長度仍不超過容量）：把新值依序放進原本的底層陣列，回傳長度增加後的切片。
2. **容量不夠**（加完所有新元素後，長度會超過容量）：配置一個**放得下全部元素的新陣列**，把舊的元素複製過去，再放入新值。回傳的切片就指向這個新陣列了。

所以不能只看目前的 `len` 是否小於 `cap`。例如長度 2、容量 3 的切片，一次加入兩個值後，長度會變成 4，仍然必須換新陣列。一次只加一個值時，才可以用 `len < cap` 判斷容量還夠。

上面某一次輸出的容量從 4 變成 8，但這不是語言保證的成長數列。每次換新陣列都要複製元素，Go 的實作通常會多留一些空間，減少搬家的次數。確切每次會變多大，由 Go 的實作決定，而且可能隨版本調整，我們不需要記，也不應該依賴它。

這也是為什麼一定要寫 `names = append(names, ...)`：容量不夠時，新切片指向的是另一個陣列，不接回來就拿不到。

## 重點整理

- `s = append(s, 值...)` 在切片尾端加入一個或多個值，結果一定要接回來。
- `len(s)` 是目前元素個數，`cap(s)` 是底層陣列從起點算起可用的格數。
- 加完所有新元素後的長度不超過容量時，`append` 重用底層陣列；超過時，會配置放得下全部元素的新陣列並複製過去。
- 容量成長的確切數字由 Go 決定，不要依賴它。
