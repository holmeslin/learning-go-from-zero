# 陣列是值、切片是 header

## 本集目標

搞懂為什麼賦值一個陣列會複製全部元素，而賦值一個切片卻會和原本的切片共用資料。

## 正文

陣列和切片寫起來很像，但被賦值或傳給函式時，行為完全不同。這一集把原因講清楚。

### 陣列是值：整個複製

陣列變數裡面**直接放著所有元素**。把它賦值給另一個變數，就是把所有元素整份複製過去：

```go
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	b := a
	b[0] = 100
	fmt.Println("a:", a)
	fmt.Println("b:", b)
}
```

執行結果：

```text
a: [1 2 3]
b: [100 2 3]
```

`b` 是一份獨立的副本，改 `b` 不會影響 `a`。傳給函式也一樣，函式拿到的是副本：

```go
package main

import "fmt"

func reset(arr [3]int) {
	arr[0] = 0
}

func main() {
	a := [3]int{1, 2, 3}
	reset(a)
	fmt.Println(a)
}
```

執行結果：

```text
[1 2 3]
```

這和 `int`、`string`、`struct` 的行為一樣，陣列就是一個普通的值。

### 切片是 header：只複製那張「小卡片」

切片變數裡面**不放元素**，只放一張小小的描述資料，叫做 **slice header**。它有三個欄位：

- 指標：指向底層陣列中，切片開始的那個位置
- 長度 `len`
- 容量 `cap`

元素本身住在底層陣列裡。所以賦值切片時，複製的只是這張 header，兩張 header 裡的指標指向**同一個底層陣列**：

```go
package main

import "fmt"

func main() {
	s := []int{1, 2, 3}
	t := s
	t[0] = 100
	fmt.Println("s:", s)
	fmt.Println("t:", t)
}
```

執行結果：

```text
s: [100 2 3]
t: [100 2 3]
```

改 `t[0]` 就是改底層陣列，透過 `s` 看當然也變了。傳給函式時也一樣，這就是第 2 章「切片作為參數」那集裡，函式可以修改呼叫者切片內容的原因。

### header 本身還是值

要特別注意：切片並不是「參考」，它的 header 仍然是被**複製**的值。所以只改 header 的操作，例如 `append` 改變了長度，就不會反映到另一個變數：

```go
package main

import "fmt"

func addItem(s []int) {
	s[0] = 100
	s = append(s, 4)
	fmt.Println("函式裡:", s)
}

func main() {
	s := make([]int, 3, 10)
	addItem(s)
	fmt.Println("函式外:", s)
}
```

執行結果：

```text
函式裡: [100 0 0 4]
函式外: [100 0 0]
```

`s[0] = 100` 改的是共用的底層陣列，所以外面看得到。`append` 雖然把 4 寫進了同一個底層陣列（容量還夠），但長度變成 4 的是函式裡那份 header；外面的 header 長度還是 3，所以看不到 4。

這也是為什麼 `append` 一定要寫成 `s = append(s, ...)`，把新的 header 接回來。函式要讓呼叫者拿到新長度，就要把切片回傳出去。

### 一張表對照

| | 陣列 `[3]int` | 切片 `[]int` |
| --- | --- | --- |
| 變數裡放什麼 | 所有元素 | header（指標、長度、容量） |
| 賦值、傳參數時複製什麼 | 全部元素 | 只有 header |
| 改元素會影響對方嗎 | 不會 | 會（共用底層陣列） |
| `append` 會影響對方嗎 | 陣列不能 `append` | 不會改到對方的長度 |

## 重點整理

- 陣列是值：賦值或傳參數會複製所有元素，彼此獨立。
- 切片變數是一個 header，包含指向底層陣列的指標、長度、容量。
- 複製切片只複製 header，兩者共用底層陣列，改元素會互相影響。
- header 本身也是值，`append` 改變的長度不會反映到其他副本，所以要用回傳值接回來。
